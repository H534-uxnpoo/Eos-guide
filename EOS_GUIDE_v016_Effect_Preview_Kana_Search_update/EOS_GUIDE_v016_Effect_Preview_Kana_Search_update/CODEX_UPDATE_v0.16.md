# EOS GUIDE v0.16 更新指示

## 目的

既存のEffect時間グラフを壊さずに、灯体の点灯状態をアニメーション表示するプレビューを追加する。
あわせて、検索欄でカタカナ語をひらがなで入力しても一致するようにする。

## 最重要：使用するデータ

- この更新パック内の `eos-guide-data-v0.15.json` を唯一の正本として使用すること。
- リポジトリ内に残っているv0.14以前のJSONや、過去の更新フォルダ内のJSONから再構成しないこと。
- 添付JSONには利用者が直接編集した内容が含まれている。既存の記事、文章、順序、表示・非表示設定、画像参照、キーボード情報を削除・巻き戻し・置換しないこと。
- JSONの変更が必要な場合も、まず同梱ファイルをそのままコピーし、今回必要な最小差分だけを加えること。

## 1. Step Based Effectへ灯体プレビューを追加

対象記事：`13_3 Step Based Effect`

現在表示されている `StepTimeline.tsx` の時間グラフ、入力欄、計算、SVG、レスポンシブ表示、アクセシビリティを保持すること。
既存グラフを別実装へ置換したり、削除したり、計算式を変更したりしないこと。

既存グラフの上部に、ch6〜ch11を表す6個の円を横並びで追加する。

- 消灯時：黒または既存テーマに合う暗色
- 点灯時：黄色
- 円の中央：チャンネル番号（6、7、8、9、10、11）
- On State／Off Stateが数値の場合は0〜100として明るさへ反映する
- In Time中は暗色から黄色へ連続的に変化する
- Dwell Time中はOn Stateを維持する
- Decay Time中はOn StateからOff Stateへ連続的に変化する
- Step Timeに従って各チャンネルの開始時刻をずらす
- 既存の重なり計算、0秒、大小関係の逆転にも対応する
- 入力値を変更したら、既存グラフと灯体プレビューを同じ状態値から即時更新する
- アニメーションは1サイクル終了後にループできるようにする

### 操作ボタン

灯体プレビュー付近に以下の3ボタンを置く。

- `▶ 再生`
- `⏸ 一時停止`
- `↺ 先頭へ`

仕様：

- 再生：現在位置から再生する。終了位置の場合は先頭から再生する
- 一時停止：現在位置を保持する
- 先頭へ：再生を停止して時刻0秒へ戻す
- 再生中は現在時刻を秒で表示する
- 連打しても複数のタイマーが同時に走らないようにする
- アンマウント時に `requestAnimationFrame` またはタイマーを確実に解除する
- `prefers-reduced-motion` が有効な環境では自動再生しない
- ボタンには日本語の `aria-label` を設定する

## 2. Absolute Effectへグラフと灯体プレビューを追加

対象記事：`13_4 Absolute Effect`

Step Based Effectと同じ見た目・操作感で、次を新規追加する。

1. ch6〜ch11の6個の灯体円
2. Absolute Effect用の時間グラフ
3. `▶ 再生`、`⏸ 一時停止`、`↺ 先頭へ`

Step Based用の入力項目をそのまま流用せず、Absoluteの記事で扱う次の値から表示を計算する。

- Time
- Dwell Time
- Level
- Grouping
- Cycle Time
- Bkgrd

Groupingによってch6〜ch11を均等に分け、各グループが順番に変化する様子を表示する。
割り切れない場合も灯体を欠落させず、先頭側のグループから1台ずつ多く割り当てる。

Levelが数値なら円の明るさへ反映する。Levelがカラーパレットまたは色として解釈できる場合はその色を使用し、色が取得できない場合は黄色を使用する。`Bkgrd`はエフェクト適用前の状態へ戻ることを示す。説明用プレビューに実際の灯体制御機能は持たせない。

実装は、Step Basedの既存グラフを複製して改変するよりも、再生制御と灯体円を共通部品化する。

推奨構成例：

```text
src/components/effects/EffectPlaybackControls.tsx
src/components/effects/FixturePreview.tsx
src/components/effects/useEffectPlayback.ts
src/components/StepTimeline.tsx          （既存グラフを保持して追加）
src/components/AbsoluteTimeline.tsx      （新規）
```

実際の既存構成に合わせて配置は調整してよい。

## 4. ひらがな検索

検索時に、検索語と検索対象文字列の両方へ同じ正規化を行う。

正規化の順序：

1. `String.prototype.normalize("NFKC")`
2. 英字を小文字化
3. カタカナを対応するひらがなへ変換
4. 前後の空白を除去
5. 連続する空白を1個へ統一

記事タイトル、summary、keywords、subtopics、本文の現在検索対象になっているフィールドをすべて同じ方法で正規化する。検索対象フィールドそのものを減らさないこと。

最低限、次を満たすこと。

| 入力 | ヒット対象 |
|---|---|
| `Effect` | Effect関連記事 |
| `effect` | Effect関連記事 |
| `エフェクト` | Effect関連記事 |
| `えふぇくと` | Effect関連記事 |
| `マジックシート` | Magic Sheet関連記事 |
| `まじっくしーと` | Magic Sheet関連記事 |
| `パッチ` | Patch関連記事 |
| `ぱっち` | Patch関連記事 |

英語を日本語読みへ自動変換する必要はない。`Effect`の記事に既にキーワード「エフェクト」があるため、カタカナ→ひらがな正規化によって「えふぇくと」が一致する設計とする。

## 6. エラー対策

- React Hooksを使用するコンポーネントが必要な構成では、既存環境に合わせてClient Component指定を行う
- `undefined.map`を起こさないよう、配列値には安全な初期値を与える
- 未知のsection typeがあっても記事全体を黒画面にしない
- Error Boundaryまたは既存のフォールバック表示を維持する
- JSONの読み込み失敗時に真っ黒な画面を表示しない
